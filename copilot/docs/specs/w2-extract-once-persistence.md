# Spec — Durable extract-once (persist the VLM result, regenerate the image) (W2)

**Status:** built. Physician question: "why extract a document twice? extract once and save it."

## Problem

Extraction (the paid **VLM** + OCR) was cached in Redis as the **full draft** (values + boxes + page
image) under a short, hours-long TTL — deliberately short for minimum-necessary PHI-at-rest. So when
that TTL expires (or Redis evicts/restarts), re-opening a document **re-runs the VLM** — wasteful in
cost + latency, and painful at 100 documents.

## Design

Split what's stored and how long:
- **Extraction result** (values + boxes + status + metadata — the expensive VLM+OCR output, *small*):
  persisted under a **long TTL (30 days — the review lifecycle)**. This is the "save it" the physician
  asked for.
- **Page image** (the *large* PHI blob): stays on the existing **short TTL**; on a miss it is
  **regenerated by re-rasterizing the PDF** (fetch + rasterize only — no VLM), not kept at rest.

`runDetectAndIngest` per document is now 3-tier:
1. full draft cache (short TTL) hit → return instantly;
2. else persisted **extraction** hit → `rasterizePages()` (VLM-free) + reattach the image → return;
3. else full extract (VLM) → persist the extraction (long) + the full draft (short).

So the **paid VLM runs exactly once ever** per document; every later open regenerates only the cheap
image.

## PHI decision (deliberate, worth noting)

The prior design kept the whole draft on a short TTL to minimize PHI-at-rest. This change keeps the
**small** extraction result (lab values — PHI) for ~30 days, while the **large** page image is NOT kept
at rest (regenerated on demand). Net: a small amount more PHI-at-rest, in the agent's **own in-boundary
Redis**, bounded to the review lifecycle, and the values are chart-bound anyway once committed. This is
the physician-requested tradeoff (save the extraction so it isn't re-run); the image — the bulkier PHI —
stays transient. TTL is configurable (`extractionTtlSeconds`).

## Boundaries

- No change to what the model/agent reads; extraction output + review UI unchanged.
- VLM-free path degrades safely: if re-rasterizing a persisted extraction fails, it falls through to a
  full re-extract.
- Offline-testable: `rasterizePages` is over the same injected ports; the VLM-once behavior is unit-tested
  (VLM ran once; image re-rasterized on re-open).

## Acceptance criteria

- **AC1** First open of a document runs the VLM once and persists the extraction result.
- **AC2** After the full-draft cache expires, re-opening does **not** re-run the VLM — it re-rasterizes
  the image and reattaches it (verified: VLM count stays 1, rasterize count increments, draft has pages).
- **AC3** A corrupt/failed persisted extraction degrades to a full re-extract, never a thrown request.
