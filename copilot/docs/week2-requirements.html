MVP Requirements at-a-glance — detailed status in the sections below

A controlled expansion of the Week 1 agent into two document types, two workers, and one regression gate. These five restate items scored in detail below, so they are shown here for orientation and not counted in the totals.

Ingest two document types

Upload and extract a lab PDF and an intake form using strict schemas.

Build basic hybrid RAG

Small guideline corpus indexed with keyword + dense retrieval and Cohere rerank (or equivalent).

Add supervisor + 2 workers

Supervisor routes to intake-extractor and evidence-retriever with logged handoffs.

Gate with eval-driven CI

50-case golden set, boolean rubrics, PR-blocking git hook.

Integrate and demo

Deployed app, source-grounded UI, latency/cost report, walkthrough video.

Delivery Stages roadmap — maps onto the scored requirements below

The narrative build order from the PDF. Shown as a roadmap; each stage's substance is scored under Core Agent Requirements / Submission / Engineering, so stages are not counted in the totals.

Stage 1Ingest lab PDF & intake form

Accept a file, associate it with a patient, store the source doc in OpenEMR, extract structured JSON, link every derived fact back to source.

Stage 2Build basic hybrid RAG

Small clinical-guideline corpus, sparse + dense retrieval, rerank candidates, return evidence snippets with source metadata. (You must source the guideline docs yourself.)

Stage 3Add supervisor + 2 workers

Small graph: supervisor decides when extraction / evidence retrieval is needed and when the final answer is ready. Explicit handoffs.

Stage 4Build the eval gate

50 cases exercising extraction, evidence retrieval, citations, refusals, missing-data. Boolean rubrics. CI fails on meaningful regression.

Stage 5Integrate, deploy & defend

Expose the Week 2 flow in the deployed app, capture traces, record a demo, map each capability back to the Week 1 user & workflow.

Critic agent

Rejects uncited claims or unsafe action suggestions.

Done (2026-07-16): a distinct critic gate = verification layer 4 now runs LAST in the graph (… → grounding → constraints → critic → respond, spec docs/specs/w2-critic.md). It vetoes any surviving claim that is uncited (belt-and-suspenders over layer 1) or is an agent-authored action suggestion — the read-only boundary (UC-4): "start her on X", "I recommend a statin", "increase the dose", "prescribe", "consider starting", "order a …" are withheld, while reporting a therapy ("the guideline recommends a statin", "propranolol 40 mg is on file", "was discontinued in 2014") passes — the deterministic detector keys on the REPORT-vs-DIRECT distinction (imperative/present verb forms, never past "-ed"). Veto-only by construction (W2_ARCHITECTURE §10): it rewrites groundedClaims to the kept subset so the body and the citation contract both exclude withheld claims; the withheld statement is never echoed (count + reason only) and never logged/shipped. If the only claim was a directive → the body degrades honestly + a boundary note ("withheld by the safety critic — surfaces and flags, does not recommend treatment or doses"); the safety findings still surface. Deterministic + offline (in @copilot/verification, a pure critique) so it runs in the eval gate; an optional thin LLM-critic seam (applyLlmVeto, also veto-only, degrade-safe) exists but is unwired by default (no hot-path latency). Common Pitfalls & Watch-Outs from the PDF — not scored

  • Trying to support five document types before two work reliably.
  • Using a VLM answer directly without schema validation or source metadata.
  • Letting the supervisor become a black box — handoffs must be logged and explainable.
  • Using LLM-as-a-judge without a clear rubric. Use boolean rubrics so failures are actionable.
  • Logging raw document text, patient identifiers, or screenshots to SaaS observability tools.
  • Final note: Week 2 is not a contest to integrate the most AI frameworks — the best submissions feel narrower than the spec and stronger for it.
